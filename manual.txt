1. THE NESTJS MENTAL MODEL
--------------------------

Request flow:

Client/Postman
    -> Controller (receives HTTP request)
    -> Service (business logic)
    -> TypeORM Repository (database commands)
    -> PostgreSQL table

Important files:

Entity     = describes a PostgreSQL table.
DTO        = describes and validates request data.
Controller = declares URLs and HTTP methods.
Service    = contains logic and database operations.
Module     = connects entity, controller and service.
AppModule  = connects the whole application and database.
main.ts    = starts NestJS and enables global features.

Golden architecture rule:

Controller -> Service -> Repository -> Database

Never put database queries in a controller.
Never create a service using new ProductService(). NestJS injects it.

main.ts:

    import { ValidationPipe } from '@nestjs/common';
    import { NestFactory } from '@nestjs/core';
    import { AppModule } from './app.module';

    async function bootstrap() {
      const app = await NestFactory.create(AppModule);

      app.useGlobalPipes(
        new ValidationPipe({
          whitelist: true,
          forbidNonWhitelisted: true,
          transform: true,
        }),
      );

      await app.listen(process.env.PORT ?? 3000);
    }

Meaning:

whitelist             = only DTO fields are accepted.
forbidNonWhitelisted  = unknown fields cause 400 Bad Request.

      @IsOptional()

    @IsOptional()
    optionalField?: string;

PATCH/partial update DTO (all fields become optional):

9. COMPLETE CRUD SERVICE TEMPLATE
---------------------------------

src/products/products.service.ts:

    import { Injectable, NotFoundException } from '@nestjs/common';
    import { InjectRepository } from '@nestjs/typeorm';
    import { ILike, Repository } from 'typeorm';
    import { CreateProductDto } from './dto/create-product.dto';
    import { PartialUpdateProductDto } from './dto/partial-update-product.dto';
    import { UpdateProductDto } from './dto/update-product.dto';
    import { Products } from './entities/products.entity';

    @Injectable()
    export class ProductsService {
      constructor(
        @InjectRepository(Products)
        private readonly productsRepo: Repository<Products>,
      ) {}

      async create(dto: CreateProductDto) {
        const product = this.productsRepo.create(dto);
        const data = await this.productsRepo.save(product);
        return { message: 'Product created successfully', data };
      }

      async findAll() {
        const data = await this.productsRepo.find({
          order: { createdAt: 'DESC' },
        });
        return { message: 'All products fetched', count: data.length, data };
      }

      async findOne(id: number) {
        const product = await this.productsRepo.findOne({ where: { id } });
        if (!product) {
          throw new NotFoundException(`Product with id ${id} not found`);
        }
        return { message: 'Product fetched', data: product };
      }

      async update(id: number, dto: PartialUpdateProductDto) {
        const { data: product } = await this.findOne(id);
        Object.assign(product, dto);
        const data = await this.productsRepo.save(product);
        return { message: 'Product updated', data };
      }

      async replace(id: number, dto: UpdateProductDto) {
        const { data: product } = await this.findOne(id);
        Object.assign(product, dto);
        const data = await this.productsRepo.save(product);
        return { message: 'Product replaced', data };
      }

      async remove(id: number) {
        await this.findOne(id);
        await this.productsRepo.delete(id);
        return { message: 'Product deleted', id };
      }

      async findByCategory(category: string) {
        const data = await this.productsRepo.find({ where: { category } });
        return { message: 'Category results', count: data.length, data };
      }

      async search(keyword: string) {
        const data = await this.productsRepo.find({
          where: { name: ILike(`%${keyword}%`) },
        });
        return { message: 'Search results', count: data.length, data };
      }

      async toggleActive(id: number) {
        const { data: product } = await this.findOne(id);
        product.isActive = !product.isActive;
        const data = await this.productsRepo.save(product);
        return { message: 'Status toggled', data };
      }
    }

Repository cheat sheet:

repo.create(dto)                 creates an entity object, not a database row.
repo.save(entity)                INSERTS new or UPDATES existing entity.
repo.find()                      SELECT all rows.
repo.findOne({ where: { id } })  SELECT one row.
repo.update(id, dto)             UPDATE without returning updated entity.
repo.delete(id)                  DELETE by id.
repo.remove(entity)              DELETE an entity already fetched.
repo.count()                     COUNT rows.

Why create then save?

    const entity = repo.create(dto); // memory only
    return repo.save(entity);        // database INSERT


10. COMPLETE CONTROLLER/API TEMPLATE
------------------------------------

src/products/products.controller.ts:

    import {
      Body, Controller, Delete, Get, Param, ParseIntPipe,
      Patch, Post, Put, Query,
    } from '@nestjs/common';
    import { CreateProductDto } from './dto/create-product.dto';
    import { PartialUpdateProductDto } from './dto/partial-update-product.dto';
    import { UpdateProductDto } from './dto/update-product.dto';
    import { ProductsService } from './products.service';

    @Controller('products')
    export class ProductsController {
      constructor(private readonly productsService: ProductsService) {}

      @Post()
      create(@Body() dto: CreateProductDto) {
        return this.productsService.create(dto);
      }

      @Get()
      findAll() {
        return this.productsService.findAll();
      }

      // Specific routes must be above :id routes.
      @Get('search')
      search(@Query('keyword') keyword: string) {
        return this.productsService.search(keyword);
      }

      @Get('category/:cat')
      findByCategory(@Param('cat') category: string) {
        return this.productsService.findByCategory(category);
      }

      @Patch(':id/toggle')
      toggle(@Param('id', ParseIntPipe) id: number) {
        return this.productsService.toggleActive(id);
      }

      @Get(':id')
      findOne(@Param('id', ParseIntPipe) id: number) {
        return this.productsService.findOne(id);
      }

      @Patch(':id')
      update(
        @Param('id', ParseIntPipe) id: number,
        @Body() dto: PartialUpdateProductDto,
      ) {
        return this.productsService.update(id, dto);
      }

      @Put(':id')
      replace(
        @Param('id', ParseIntPipe) id: number,
        @Body() dto: UpdateProductDto,
      ) {
        return this.productsService.replace(id, dto);
      }

      @Delete(':id')
      remove(@Param('id', ParseIntPipe) id: number) {
        return this.productsService.remove(id);
      }
    }

Decorator cheat sheet:

@Controller('products') = base URL /products
@Get()                  = HTTP GET
@Post()                 = HTTP POST
@Put(':id')             = HTTP PUT with route parameter
@Patch(':id')           = HTTP PATCH with route parameter
@Delete(':id')          = HTTP DELETE
@Body()                 = JSON request body
@Param('id')            = value inside URL
@Query('keyword')       = value after ?keyword=
ParseIntPipe            = validates/converts id to number

HTTP meaning:

POST   create a new record
GET    read records
PUT    fully replace a record; required fields must be sent
PATCH  partially change a record
DELETE remove a record


11. QUERY, FILTER, SEARCH, SORT AND PAGINATION
----------------------------------------------

Exact match:

    repo.find({ where: { category: 'Electronics' } });

Multiple AND conditions:

    repo.find({ where: { category: 'Electronics', isActive: true } });

Case-insensitive contains search:

    import { ILike } from 'typeorm';
    repo.find({ where: { name: ILike(`%${keyword}%`) } });

Greater than / less than:

    import { MoreThan, LessThan } from 'typeorm';
    repo.find({ where: { price: MoreThan(100) } });
    repo.find({ where: { stock: LessThan(10) } });

Between:

    import { Between } from 'typeorm';
    repo.find({ where: { price: Between(100, 500) } });

IN list:

    import { In } from 'typeorm';
    repo.find({ where: { category: In(['Sports', 'Electronics']) } });

Sort newest first:

    repo.find({ order: { createdAt: 'DESC' } });

Pagination:

    const page = 1;
    const limit = 10;
    repo.find({
      skip: (page - 1) * limit,
      take: limit,
      order: { createdAt: 'DESC' },
    });

Pagination controller:

    @Get('page')
    paginate(
      @Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number,
      @Query('limit', new DefaultValuePipe(10), ParseIntPipe) limit: number,
    ) {
      return this.productsService.paginate(page, limit);
    }

Select only some columns:

    repo.find({ select: { id: true, name: true, price: true } });

Count:

    const count = await repo.count({ where: { isActive: true } });

Important route order:

    @Get('search')
    @Get('category/:cat')
    @Get(':id')

Put search/category before :id, or Nest may treat "search" as an id.

Install:

    npm install @nestjs/platform-express multer
    npm install -D @types/multer @types/express

Controller imports:

    import {
      BadRequestException, Param, Post, UploadedFile, UseInterceptors,
    } from '@nestjs/common';
    import { FileInterceptor } from '@nestjs/platform-express';
    import { diskStorage } from 'multer';
    import { extname } from 'path';

Controller route:

    @Post(':id/upload')
    @UseInterceptors(
      FileInterceptor('file', {
        storage: diskStorage({
          destination: './uploads',
          filename: (_request, file, callback) => {
            callback(null, `${Date.now()}-${file.originalname}`);
          },
        }),
        fileFilter: (_request, file, callback) => {
          const allowed = ['.jpg', '.jpeg', '.png', '.pdf'];
          if (!allowed.includes(extname(file.originalname).toLowerCase())) {
            return callback(
              new BadRequestException('Only JPG, JPEG, PNG and PDF are allowed'),
              false,
            );
          }
          callback(null, true);
        },
        limits: { fileSize: 2 * 1024 * 1024 },
      }),
    )
    upload(
      @Param('id') id: string,
      @UploadedFile() file: Express.Multer.File,
    ) {
      return this.courseService.uploadCourseMaterial(id, file);
    }

Service:

    uploadCourseMaterial(id: string, file: Express.Multer.File) {

      return {
        message: 'Material uploaded successfully',
        courseId: id,
        filename: file.filename,
        path: file.path,
      };
    }

13. DEPENDENCY INJECTION PATTERNS
--------------------------------

A. Same module (intra-module):

    @Injectable()
    export class CourseService {}

    @Controller('course')
    export class CourseController {
      constructor(private readonly courseService: CourseService) {}
    }

    @Module({
      controllers: [CourseController],
      providers: [CourseService],
    })
    export class CourseModule {}

B. Different modules (inter-module):

Providing module must export:

    @Module({
      providers: [CourseService],
      exports: [CourseService],
    })
    export class CourseModule {}

Consuming module must import:

    @Module({
      imports: [CourseModule],
      providers: [EnrollmentService],
    })
    export class EnrollmentModule {}

Consuming service injects normally:

    constructor(private readonly courseService: CourseService) {}

C. Circular dependency:

EnrollmentModule:

    imports: [forwardRef(() => NotificationModule)],
    providers: [EnrollmentService],
    exports: [EnrollmentService],

NotificationModule:

    imports: [forwardRef(() => EnrollmentModule)],
    providers: [NotificationService],
    exports: [NotificationService],

EnrollmentService constructor:

    constructor(
      @Inject(forwardRef(() => NotificationService))
      private readonly notificationService: NotificationService,
    ) {}

NotificationService constructor:

    constructor(
      @Inject(forwardRef(() => EnrollmentService))
      private readonly enrollmentService: EnrollmentService,
    ) {}

Required import:

    import { forwardRef, Inject, Injectable } from '@nestjs/common';

Circular DI needs forwardRef on BOTH module imports and BOTH service injections.


14. RELATIONSHIPS
-----------------

RELATIONSHIP QUICK DECISION

Ask: "How many A can connect to how many B?"

One-to-one:
    One User has one Profile.
    One Profile belongs to one User.

One-to-many / many-to-one:
    One Category has many Products.
    Each Product belongs to one Category.

Many-to-many:
    One Student takes many Courses.
    One Course has many Students.

Database result:

One-to-one       -> one foreign-key column with a UNIQUE constraint.
One-to-many      -> foreign key is stored on the "many" side.
Many-to-many     -> TypeORM creates a third/junction table.

Important words:

Owning side = side that physically controls the foreign key/join table.
Inverse side = other side used for navigation.
Relation property = object such as product.category, not categoryId by default.
Join column = foreign-key column.
Junction table = table joining two many-to-many entities.


14A. ONE-TO-ONE: USER AND PROFILE
---------------------------------

Goal:

    User 1 <-> Profile 1

The side containing @JoinColumn() is the owner. Put @JoinColumn() on ONE side only.
Here User owns the relationship, so the users table stores profileId.

profile.entity.ts:

    import { Column, Entity, OneToOne, PrimaryGeneratedColumn } from 'typeorm';
    import { User } from './user.entity';

    @Entity('profiles')
    export class Profile {
      @PrimaryGeneratedColumn()
      id: number;

      @Column()
      bio: string;

      @Column({ nullable: true })
      phone?: string;

      @OneToOne(() => User, (user) => user.profile)
      user: User;
    }

user.entity.ts:

    import {
      Column, Entity, JoinColumn, OneToOne, PrimaryGeneratedColumn,
    } from 'typeorm';
    import { Profile } from './profile.entity';

    @Entity('users')
    export class User {
      @PrimaryGeneratedColumn()
      id: number;

      @Column()
      name: string;

      @OneToOne(() => Profile, (profile) => profile.user, {
        cascade: true,
        nullable: true,
      })
      @JoinColumn()
      profile?: Profile;
    }

Approximate database tables:

    profiles: id, bio, phone
    users:    id, name, profileId (UNIQUE foreign key)

Create nested User + Profile using cascade:

DTOs:

    export class CreateProfileDto {
      @IsString()
      @IsNotEmpty()
      bio: string;

      @IsOptional()
      @IsString()
      phone?: string;
    }

    export class CreateUserDto {
      @IsString()
      @IsNotEmpty()
      name: string;

      @IsOptional()
      @ValidateNested()
      @Type(() => CreateProfileDto)
      profile?: CreateProfileDto;
    }

DTO imports:

    import { Type } from 'class-transformer';
    import {
      IsNotEmpty, IsOptional, IsString, ValidateNested,
    } from 'class-validator';

Service:

    async create(dto: CreateUserDto) {
      const user = this.userRepo.create(dto);
      return this.userRepo.save(user);
    }

Because cascade: true is enabled, saving User also saves the nested Profile.

POST /users body:

    {
      "name": "Ayesha",
      "profile": {
        "bio": "Computer Science student",
        "phone": "01700000000"
      }
    }

Load user with profile:

    return this.userRepo.find({
      relations: { profile: true },
    });

Load one:

    return this.userRepo.findOne({
      where: { id },
      relations: { profile: true },
    });

Attach an existing profile without cascade:

    const user = await this.userRepo.findOneBy({ id: userId });
    const profile = await this.profileRepo.findOneBy({ id: profileId });
    if (!user || !profile) throw new NotFoundException('User or profile not found');
    user.profile = profile;
    return this.userRepo.save(user);

Remove only the link (keep profile row):

    user.profile = null;
    await this.userRepo.save(user);

The entity property must allow null:

    profile: Profile | null;

If the foreign key should live in profiles instead, move @JoinColumn() to Profile.user.


14B. ONE-TO-MANY / MANY-TO-ONE: CATEGORY AND PRODUCT
-----------------------------------------------------

Goal:

    Category 1 -> Product 1
               -> Product 2
               -> Product 3

This is one relationship described from two directions:

Category -> Products is @OneToMany.
Product -> Category is @ManyToOne.

The foreign key ALWAYS belongs on the many side: products.categoryId.
@OneToMany cannot exist alone; it needs @ManyToOne on the other entity.

category.entity.ts:

    import { Column, Entity, OneToMany, PrimaryGeneratedColumn } from 'typeorm';
    import { Product } from './product.entity';

    @Entity('categories')
    export class Category {
      @PrimaryGeneratedColumn()
      id: number;

      @Column({ unique: true })
      name: string;

      @OneToMany(() => Product, (product) => product.category)
      products: Product[];
    }

product.entity.ts:

    import {
      Column, Entity, JoinColumn, ManyToOne, PrimaryGeneratedColumn,
    } from 'typeorm';
    import { Category } from './category.entity';

    @Entity('products')
    export class Product {
      @PrimaryGeneratedColumn()
      id: number;

      @Column()
      name: string;

      @Column({ type: 'decimal', precision: 10, scale: 2 })
      price: number;

      @ManyToOne(() => Category, (category) => category.products, {
        nullable: false,
        onDelete: 'RESTRICT',
      })
      @JoinColumn({ name: 'categoryId' })
      category: Category;
    }

@JoinColumn is optional on @ManyToOne, but adding it lets you choose categoryId as the
foreign-key column name.

Approximate database tables:

    categories: id, name
    products:   id, name, price, categoryId

CreateProductDto should receive categoryId, not an entire Category object:

    export class CreateProductDto {
      @IsString()
      @IsNotEmpty()
      name: string;

      @Type(() => Number)
      @IsNumber()
      @IsPositive()
      price: number;

      @Type(() => Number)
      @IsInt()
      @IsPositive()
      categoryId: number;
    }

Module must register both repositories if one service uses both:

    @Module({

Deletion choices on @ManyToOne:

    onDelete: 'RESTRICT'  -> cannot delete a category that still has products.
    onDelete: 'CASCADE'   -> deleting category also deletes its products. Dangerous.
    onDelete: 'SET NULL'  -> product remains and categoryId becomes null.

For SET NULL, relationship must use nullable: true:

    @ManyToOne(() => Category, ..., {
      nullable: true,
      onDelete: 'SET NULL',
    })
    category: Category | null;

Exam-safe default: use RESTRICT unless the question explicitly requests another behavior.

-------------------------------------

Goal:

    Student 1 -> Course A, Course B
    Student 2 -> Course A, Course C

TypeORM creates a junction table. Put @JoinTable() on ONE side only. That side is the owner.
Here Student is the owner.

    import { Column, Entity, ManyToMany, PrimaryGeneratedColumn } from 'typeorm';

    export class Course {

      @Column()
      name: string;

      @Column({ unique: true })
      code: string;

      @ManyToMany(() => Student, (student) => student.courses)

    import {
      Column, Entity, JoinTable, ManyToMany, PrimaryGeneratedColumn,
    } from 'typeorm';
    import { Course } from './course.entity';

    @Entity('students')

      @PrimaryGeneratedColumn()
      id: number;

      name: string;

        where: { id: studentId },
        relations: { courses: true },
      });
      const course = await this.courseRepo.findOneBy({ id: courseId });

      if (!student || !course) {
        throw new NotFoundException('Student or course not found');
      }

      if (!alreadyAdded) student.courses.push(course);

      return this.studentRepo.save(student);
    }

      const student = await this.studentRepo.findOne({
        where: { id: studentId },
        relations: { courses: true },
      });
      if (!student) throw new NotFoundException('Student not found');

      student.courses = student.courses.filter((course) => course.id !== courseId);
      return this.studentRepo.save(student);
    }

Replace all course links:

    async replaceCourses(studentId: number, courseIds: number[]) {
      const student = await this.studentRepo.findOneBy({ id: studentId });
      if (!student) throw new NotFoundException('Student not found');

      const courses = await this.courseRepo.findBy({ id: In(courseIds) });
      if (courses.length !== courseIds.length) {
        throw new NotFoundException('One or more courses not found');

      student.courses = courses;
      return this.studentRepo.save(student);
    }

14D. WHEN MANY-TO-MANY NEEDS AN EXTRA ENTITY
--------------------------------------------

Do not use a simple @ManyToMany when the connection itself has fields.

Example: Student enrolls in Course, and enrollment needs:

    enrollmentDate
    grade
    status

Create an Enrollment entity instead:

    @Entity('enrollments')
    export class Enrollment {
      @PrimaryGeneratedColumn()
      id: number;

      @ManyToOne(() => Student, (student) => student.enrollments)
      student: Student;

      @ManyToOne(() => Course, (course) => course.enrollments)
      course: Course;

      @CreateDateColumn()
      enrollmentDate: Date;

      @Column({ nullable: true })
      grade?: string;

      @Column({ default: 'active' })
      status: string;
    }

Student:

    @OneToMany(() => Enrollment, (enrollment) => enrollment.student)
    enrollments: Enrollment[];

Course:

    @OneToMany(() => Enrollment, (enrollment) => enrollment.course)
    enrollments: Enrollment[];

This converts one many-to-many into two one-to-many relationships:

    Student 1 -> many Enrollments
    Course  1 -> many Enrollments

Rule: if the junction needs its own data, create a real junction entity.


14E. LOADING RELATIONS
----------------------

Relations are not loaded automatically by default.

Repository find options:

    repo.find({ relations: { category: true } });

Nested relation:

    studentRepo.find({
      relations: {
        enrollments: {
          course: true,
        },
      },
    });

QueryBuilder for more control:

    return this.productRepo
      .createQueryBuilder('product')
      .leftJoinAndSelect('product.category', 'category')
      .where('category.name = :name', { name: 'Electronics' })
      .orderBy('product.createdAt', 'DESC')
      .getMany();

LEFT JOIN includes parent rows even if relation is null.
INNER JOIN includes only rows that have a matching relation.

Avoid eager: true in exams unless requested. Explicit relations are easier to understand and
avoid accidentally returning large nested objects.


14F. CASCADE, ON DELETE AND ORPHANS
-----------------------------------

These are different concepts:

cascade: true
    TypeORM operation behavior. Saving a parent can automatically save related objects.

onDelete: 'CASCADE'
    Database behavior. Deleting the referenced parent deletes child rows.

orphanedRowAction
    Behavior when children are removed from a parent's collection and parent is saved.

Safer selective cascade:

    cascade: ['insert', 'update']

This permits nested insert/update but not automatic removal.

Be careful with cascade: true on request data. A client may create/update nested records you did
not intend. For exam questions, use it only when nested creation is explicitly wanted.

Common onDelete choices:

RESTRICT / NO ACTION -> protect child records and reject parent deletion.
CASCADE              -> delete children with parent.
SET NULL             -> keep children and clear nullable foreign key.


14G. RELATION ID WITHOUT LOADING THE OBJECT
-------------------------------------------

Sometimes you want categoryId in the response without loading Category.

Option 1: explicit foreign-key column plus relation:

    @Column()
    categoryId: number;

    @ManyToOne(() => Category, (category) => category.products)
    @JoinColumn({ name: 'categoryId' })
    category: Category;

Both properties refer to the same database column.

Option 2: @RelationId:

    @RelationId((product: Product) => product.category)
    categoryId: number;

Import RelationId from typeorm.

14J. RELATIONSHIP ERRORS AND FAST FIXES
---------------------------------------

"Entity metadata for X#relation was not found"
    Import the correct entity and ensure it is registered through forFeature or autoLoadEntities.

"Cannot query across one-to-many"
    Use supported nested find options or QueryBuilder; query from the many-side when simpler.

Relation returns undefined or []
    Add relations: { relationName: true } to find/findOne.

Foreign-key violation
    The related id does not exist, or deletion is restricted. Find related row first and throw a
    clear NotFoundException.

Duplicate key in junction table
    Check whether the link already exists before pushing it into the relation array.

Saving relation deletes old links
    Assigning student.courses = newArray replaces all links. To add one, first load current
    courses and push the new course.

Infinite/circular JSON response
    Do not manually return entity graphs where both sides recursively reference each other.
    Repository-loaded relations normally avoid this, but custom object construction can cause it.

Wrong foreign-key location
    One-to-many foreign key belongs on @ManyToOne side. One-to-one foreign key belongs where
    @JoinColumn is placed. Many-to-many junction ownership belongs where @JoinTable is placed.

RELATIONSHIP MEMORY FORMULA

    @JoinColumn once for one-to-one.
    Foreign key on @ManyToOne side for one-to-many.
    @JoinTable once for many-to-many.
    Load relations explicitly.
    Find related rows before linking.
    Save the owning entity after link/unlink.
    Junction data means create a junction entity.
